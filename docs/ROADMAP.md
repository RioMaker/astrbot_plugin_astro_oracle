# 星轨神谕开发路线

本文记录后续设计与验收要求。**除 P0 的插件骨架外，其余阶段及数据接口均为规划，尚未实现。**

方案参考用户提供的 [公开讨论](https://chatgpt.com/share/6ac87d35-4590-83e8-977c-329d44d16ea4)。项目目标是还原指定时间与地点的真实天文状态，并探索可在独立数据上验证的关联；天文数据的准确性与关联研究的有效性分别验收。

## 阶段任务

| 任务 | 依赖 | 范围 | 验收条件 |
| --- | --- | --- | --- |
| P0 · 插件骨架 | 名称与范围确认 | 独立仓库、元数据、配置、基础说明指令、规范和规划 | 命名一致；Ruff、语法及本地指令冒烟通过；同步迁移清单 |
| P1 · 天文计算核心 | P0 | 时间/地点规范、太阳/月球/主要行星状态、来源和误差记录 | 使用真实历表；跨年份、时区、经纬度案例与权威计算结果核对；明确误差与覆盖范围 |
| P2 · 恒星与特征 | P1 | 接入适量恒星目录、位置传播、空间几何特征和特征版本 | 来源可追溯；缺失运动参数有质量标记；相同输入和版本可复算；验证批量性能 |
| P3 · 研究样本 | P1 的接口稳定 | 经同意的资料与统一测量、匿名标识、质量记录 | 样本与天文状态分离；记录时间地点误差及来源；验证访问、导出和删除边界 |
| P4 · 对照实验 | P2、P3 | 时间地点基线、逐层天文特征、随机对照、分组与独立留出验证 | 冻结确认性假设；记录数据切分和模型版本；报告独立集结果及不确定性，包括无增益的结果 |
| P5 · 范围扩展 | P1；研究扩展依赖 P4 | 更长日期范围、更多天体、可选外部客户端 | 逐模型标明覆盖和精度；性能有实测；超出可靠范围的输出明确标记 |

## 模块与接口规划

AstrBot 入口负责指令解析、权限与结果展示。天文引擎只接收规范化时间地点和计算选项，返回天体状态。特征层在状态上生成带版本的数值表示；研究评估使用单独的样本与特征表。

计划接口为 `compute_state(time_location, options) -> state_snapshot`，以及 `extract_features(state_snapshot, profile) -> feature_snapshot`。返回值的实际 Python 类型、字段和单位在 P1/P2 中确认，当前不创建空壳算法或伪造结果。

| 对象 | 计划记录的信息 |
| --- | --- |
| `time_location` | 原始日期与历法、天文纪年、时区或显式偏移、时间尺度、规范化时刻、经纬度/高度、输入精度和来源 |
| `state_snapshot` | 标准化输入、天体标识、坐标中心和框架、位置/速度及单位、数据质量、模型适用范围、数据与算法版本/校验值 |
| `feature_snapshot` | 状态来源、特征配置和版本、特征值、缺失标记及不确定性处理方式 |
| `research_sample` | 匿名样本标识、同意与资料来源、观测指标及测量质量、必要混杂变量；与状态和特征通过标识关联 |
| `experiment_run` | 假设、样本与特征版本、数据切分、基线及对照、模型和随机种子、指标及不确定性 |

公共历表和恒星目录保存一份，按版本引用；避免为每个样本重复保存整套星表。缓存标识必须包含规范化时间地点、坐标选项、数据版本和计算版本。

## 日期范围和数据选择

从设计阶段为长跨度日期保留表示能力，区分可表示日期、数据覆盖日期和经过精度验证的日期。现代研究、历史天文模拟和长期近似模拟分别标明适用范围。

长跨度日期不能只依赖 Python `datetime`；应明确历法、天文纪年（含公元 0 年的规则）和规范化时间表示。太阳系历表覆盖、自行传播、岁差/地球自转、历史民用时间转换分别核对，不能因一个模型支持某年份就声明整套输出均适用。

P1 核对 JPL 历表与时间系统，P2 再按恒星运动参数完整度和计算成本选择 Hipparcos/Gaia 等目录。具体日期边界、首批天体数量、数据文件大小和误差阈值在真实资源核对与测量后确定，不从分享方案直接继承精度承诺。

## 验证原则

- 天文计算使用真实来源，与 JPL Horizons 或合适的独立实现比较；保存输入、坐标定义、单位、误差和来源版本。
- 天文状态由时间与地点决定。研究中的增益应与充分表达时间地点的基线比较，考虑季节、地区、年代和采样偏差。
- 探索与确认性验证分开；特征和模型选择不能使用最终留出集。随机对照、多重比较、分组泄漏和跨人群重复性按实验目标设计。
- 输出区分数据事实、模型近似、探索性发现和已通过独立验证的结果。
- 当前的插件骨架检查不证明真实 AstrBot/OneBot 集成，也不证明任何天文精度或人格预测能力。
