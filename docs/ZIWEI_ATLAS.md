# 紫微星图 · 天球与命盘

`/紫薇星图` 与 `/紫微星图` 使用同一个独立指令入口，输出 `2440 × 1810` PNG。旧 `/星图`、`/xingtu`、`/xt`、`/star` 保持原有双半球图。

## 图片内容

左侧是观测地点的全天方向：北上东左、天顶居中，半径一半的圆环是地平线；实心星点在地平线上方，空心在下方。17 个真实目标的位置和星等来自已有计算，文字避让不移动星点。星名次行显示“现代天体简称 · 传统宫支”，`*` 紧随采用展示约定的天体简称。

灰色细边界由球面最近星种子分区得到，同宫内部边合并；命宫关联片区用淡紫突出。宫名只在整个文字框均属于该关联宫的空白区域内排布，狭小片区不挤放标签，可通过星名次行和底部索引查询。同宫可有多片，没有实体种子的宫不分配天区，数值等距异宫用中性边界色表示。

右侧保持传统十二宫方盘。25 个静态星曜的名称、四化与命身标记留在本宫，固定编号与天球对应；`—` 表示当前没有采用单体映射。底部索引列出宫位、高度、方位。

整体沿用用户提供的 Linear 风格：近黑背景、白色主文字、灰色次文字、克制细边框与淡紫强调，不添加纹理或光晕。Inter 派生字体用于英数，已有 AstroSans 补全中文，来源和许可见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

## 数据含义

区域公式为 `b(v,t)=传统落宫(argmax_i v·v_i(t),t)`：先使用真实天体方向与传统排盘标签，再生成关联区域。因此它是明确的表达模型，不能当作反推得到了古人的物理宫界。模型限制、候选反推结果和来源见 [几何研究说明](ZIWEI_GEOMETRY_INFERENCE.md)。

原有对应分级继续保留：2 个日月实体、7 个北斗历史别名、8 个展示约定。历法、时区与安星规则未调整；天球依然是同一时刻地点、站心视方向、无折射。每次指令重新计算请求时刻，无参数使用当前时刻，不在群里自动刷新或推送。

## 生成与验收

只输入时间也可排盘，例如 `/紫薇星图 20261014200000` 或 `/紫微星图 2026-10-14 20:00:00`。未改配置时采用北京地点与北京时间（`Asia/Shanghai`）；只给日期 `/紫薇星图 20261014` 时补齐为 `08:00:00`。自定义默认地点、补齐时间和显式 `tz=...` 继续生效。

```powershell
.\.venv\Scripts\python.exe -m tools.preview_ziwei_atlas --input '/紫薇星图 北京 20261012200000'
```

显式预览默认写入 `data/ziwei-validation/atlas/beijing.png`，配套 JSON 包含真实数据、对应类别、宫内／星名／区域名框、区域模型含义、未放置标签的宫支，以及图片、代码、字体 SHA。AstrBot 指令和 LLM 工具调用同一渲染器，在共享计算线程返回内存图片；QQ 群显式日期请求会按配置保存[调用记录](ZIWEI_CALLS.md)，图片不落盘。

旧 `tools.preview_ziwei_linear` 仍生成上一版无关联区对照图，便于研究比对。本轮本地图片与服务验收记录见 [验证记录](VALIDATION.md)；实际 AstrBot／OneBot／QQ 回图仍须在运行端联合验收。
